# ADR-0015 — 外殼式導覽：分頁 + 常駐 mini player，播放器與逐字稿是升起的覆蓋層

- **Status:** accepted
- **Date:** 2026-08-07

## Context

原本的版面是「播放器即首頁」：`App.tsx` 直接畫播放器，探索清單（`PodcastBrowser`）
是播放器上半部的一塊，逐字稿面板則排在所有播放控制之後。W3 實機使用後，三個問題
同時浮出來，而它們其實是同一個結構問題的三種症狀：

1. **逐字稿跟不上語音。** 面板排在封面、進度條、transport、pill 列之後，在 iPhone
   上只分到約三成高度、一次看得到五六行。跟播捲動在那種視窗裡不像「跟著唸」，像
   「清單在抖」。當前句與其他句又只差一階灰、字級幾乎一樣，動起來更認不出來。
2. **聽東西的時候回不了首頁。** 沒有「首頁」這個概念可回——播放器就是首頁，而探索
   清單被逐字稿展開時整塊 `display:none` 掉了。
3. **`PodcastBrowser` 的清單寫死 `maxHeight: 320 / 232`**，因為它必須讓出空間給
   下面的播放器。那是版面債，不是設計。

考慮過的選項：

- **把逐字稿面板加高** —— 治標。空間是跟播放控制搶的，加高就等於把控制項擠掉。
- **逐字稿改用 Modal** —— 高度有了，但 `TermSheet` 本身是 Modal，iOS 上兩層 Modal
  的 present 時機有坑（第二層可能不顯示）。
- **改成 podcast app 的標準外殼** —— 空間問題與導覽問題一次解決。

## Decision

`App.tsx` 收斂成**外殼**，只做三件事：擁有播放器、擁有導覽狀態、把兩者接起來。

```
┌───────────────────────────┐
│ 分頁內容（探索 ／ 練習）   │  ← 各自吃滿整個畫面
├───────────────────────────┤
│ MiniPlayer                │  ← 常駐，點了往上升起
│ 分頁列                     │
└───────────────────────────┘
     ↑ NowPlaying 覆蓋上來
          ↑ TranscriptScreen 再覆蓋上來
```

覆蓋層用**絕對定位**而不是 `Modal`，正是為了讓身為 Modal 的 `TermSheet` 天生疊在
它們上面。root 不放 `paddingTop`——RN 的 `top: 0` 對齊的是父層 padding box，root 有
上緣留白的話覆蓋層會少掉那一塊、再加上自己的留白就變成兩倍。

播放狀態（player 實例、`seekTarget`、rate、events）全部留在外殼：它是跨畫面的，
誰在最上層都不該影響「現在聽到哪裡」。子畫面只收值與 callback，唯一的例外是拖曳中
的 `scrubSec`——它是本地的，因為手指經過的每個位置都可能觸發一個 10 分鐘窗口的
Whisper 轉錄，放開手才算數。

「現在唸到哪一句」用**三個訊號同時**表達：字級（21 vs 18）、亮度（`text` vs `dim`
vs `faint`）、左側 3px 的藍色標記。藍色在 `theme.ts` 的語意是「中性 chrome ＝進度」，
用在這裡正確——它表達的是播放位置，不是「你動手了」（綠）也不是「app 在猜」（琥珀）。

## Consequences

**變容易的**：逐字稿拿到整個畫面，跟播看得出來是在跟播。探索與練習各自有完整版面，
`PodcastBrowser` 的 `maxHeight` 限制可以拿掉。在任何畫面都能回到探索頁（分頁列）
或倒帶（mini player 上的 ↺15）。`App.tsx` 從 803 行降到 479 行。

**變難的 / 被綁住的**：

- 多了一層「開啟播放器」的動作才看得到大封面與速度控制。用 mini player 常駐
  ↺15 與播放鍵抵銷——核心手勢在任何畫面都是一鍵。
- 覆蓋層是自己管的 state，不是 navigation stack。之後若要加第三層（例如單集詳情），
  再堆 boolean 就會開始糊，那時應該換成真的 navigator 並 supersede 這份。
- 沒有安裝 safe-area 套件，上下留白用平台常數頂替（`TOP_INSET`）。換裝置尺寸時
  要回來看這個數字。
- **逐字稿仍然必須主動打開**。它平常不在畫面上，所以「打開」這個動作才保有訊號
  意義——「rewind 之後打開逐字稿」是把 capture 升級成 ★★★ strong 的三個條件之一
  （signal-design §2）。做成常駐面板的話這個條件永遠成立，等於沒有這個條件。
  這一點不因為版面改變而放寬。

**沒有 supersede 任何 ADR。** ADR-0002（自己做播放器）、ADR-0003（單一 replay-event
pipeline）都原封不動：新的兩個畫面各自有進度條，但兩邊的往回拖都走同一個 `onSeek`
回到外殼的 `logReplayEvent`。
