# ADR-0025 — Mirror 三層音訊階梯用**預生成的原生慢速**，不用 `setPlaybackRate`；診斷延後到他先給答案之後

- **Status:** accepted
- **Date:** 2026-08-14

## Context

本輪動了練習頁 step c（揭露 → 診斷）與 step d（重聽）兩處。合成一份 ADR 是因為兩處受
**同一條閘**管：

> **答案不准在他自己下判斷之前出現。**

慢速／分塊的音檔會把**詞界唸給他聽**——那是答案的一種；診斷卡直接寫出 `focus_phrase`
——那是答案本身。兩者分開實作、共用一條原則，分開記會讓下一個人只搬走其中一半。

背景的兩個事實：

1. **`setPlaybackRate(0.7)` 已經在畫面上一段時間了**（重聽那顆玻璃膠囊）。它便宜、零素材、
   立刻可用，所以很容易被當成「慢速那一級已經有了」。本輪要記下的正是**它不是那一級**。
2. **這個 app 唯一的資產是「學習者自己指出來的斷點」**（ADR-0017 的框選訊號、`captureEngine`
   的倒帶窗口，都是同一件事的不同入口）。診斷卡是我們的**猜測**，先出現就會污染那個資產。

### 被否決的方案

| 方案 | 為什麼不用 |
| --- | --- |
| **`setPlaybackRate(0.7)` 直接當第二級** | 見 Decision ①。時間伸縮不生邊界，而學習者卡住的正是邊界。 |
| **素材查不到就顯示 disabled 的按鈕／「載入失敗」** | 那是在跟他報告一件與他無關的事（我們的檔還沒生）。disabled 的按鈕會被讀成「app 壞了」，而它其實好好的。 |
| **`capture.id` 當音檔檔名** | 裝置端當場 `uuidv4()` 生的，離線預生成不可能事先知道。key 只能是**內容本身算得出來**的東西。 |
| **`weak` / `strong` 也推路徑** | 倒帶窗口起點是 T−15 的任意浮點，事後還會被 `windowsOverlap` 合併收窄，永遠對不上任何一句 cue 的起點。硬推的下場不是 404，是**猜中別句**。 |
| **靠 `diagnosing` 的非同步延遲當「延後」** | 複習卡與二次進入的卡，`diagnosis` 早就在 store 裡，會在按下「看逐字稿」的**同一幀**整張出現。延後必須是明確的閘，不是賭 round trip 比人慢。 |
| **揭露全文之前就問「卡在哪」** | 他還沒看到字，指不出詞界；而且會逼他用聽的去指，那是另一個題目（也更難答）。 |
| **把 noticing 併進既有評分列（再來一次／記住了／太簡單）** | 評分機制本輪明令不動。而且評分測的是「這張卡還要不要再出現」，noticing 測的是「你覺得斷在哪」——兩把不同的尺背靠背。 |

## Decision

### ① 三層階梯；第二級必須是**離線預生成的原生慢速**

```
① Mirror·分塊   塊內原速 + thought group 邊界停頓   ← 教學價值最高
② Mirror·慢速   原生慢速（母音與停頓拉長、子音幾乎不變）
③ 原音          真實速度                            ← 驗收
```

**為什麼不用 `setPlaybackRate(0.7)` 冒充 ②**——時間伸縮把每個音段**等比**拉長，真實的慢速
朗讀不是那樣：

1. **音段時長不是等比的。** 真實慢速主要拉長母音與停頓，子音幾乎不變。等比拉長會毀掉
   tense/lax 母音的**時長比**這條線索，而那是英語母音對立最可靠的線索之一。
2. **塞音的爆破被抹開。** closure + burst 被拉長之後，burst 從一個瞬時事件變成一段糊掉的
   東西——那是偵測**詞界**最強的線索之一。
3. **F0 輪廓被拉長成假語調。** 他跟著念，念到的是一個沒有人會這樣說的句子。
4. 🔴 **而且弱讀還是弱讀。** "wanna" 放慢仍然是 "wanna"，`gonna` 放慢仍然沒有那個 t。
   **學習者要的是邊界，拉長不會生出邊界**，只是把同一團糊的東西播久一點。

第 4 點也直接決定了**① 分塊的教學價值高於 ② 慢速**：分塊是唯一真的在**製造邊界**的一級
——塊內維持原速（連音、弱讀、節奏全部還在，所以聽到的仍是真英語），只在 thought group
的邊界插停頓。他學到的是「這串聲音該切在哪」，不是「慢慢再聽一次」。

所以順序是 ① → ② → ③，而且**寫成一行字放在按鍵下面**：三顆鍵擺在一起看不出先後，
而先後正是它的教學價值。

③ **刻意不進 `MirrorPaths`**：原音不是新素材，它就是那一集本來就在播的檔案，大綠圓鍵已經
用 `playSegment` 播它了。多開一個欄位只會讓下游以為要再下載一份。

### ② 素材定位是純函式；查不到就**整個區塊不顯示**

`lib/mirrorAudio.ts` 只 import `fetchWithTimeout`（不碰 store / expo-audio / React），
所以路徑推導可以在沒有 app 的情況下單獨驗證。

- **白名單** `MIRROR_ELIGIBLE_STRENGTHS = ['selected', 'saved']`，**不准改寫成 `!== 'weak'`**：
  黑名單會讓將來新增的級別預設被算進來，然後拿一個對不上的 key 去猜檔名。
- **key = `round1(cue.start) * 1000` 的毫秒整數**。先 round1 再乘 1000，與 capture 寫進 store
  的精度同一套，否則浮點尾巴會讓同一句話在不同裝置上算出不同檔名。
- **產檔命名契約寫在 `mirrorAudio.ts` 的檔頭**（`demo-media/<slug>/mirror/<key>-chunked.mp3`
  / `-slow.mp3`）。寫在那裡是因為下一輪寫產檔腳本的人只會讀那個檔；沒有它，他一定會自己
  發明一套命名，然後兩邊永遠對不上。
- **任何一條不確定就回 `null`**（沒有 `transcriptUrl`、帶 query string、不是自家 demo-media、
  `windowStart` 不合法）。猜錯路徑的下場不是 404，是播出一句「聽起來很合理但根本是別句」的
  音檔——**那是這個畫面上最難被發現的一種錯**。
- 存在性用 **HEAD**，判定**只看 `res.ok`**（Supabase Storage 物件不存在時常回 400 而不是
  404），任何非 ok / 逾時 / 網路爆炸一律當「沒有素材」，不 throw、不印 warning——素材不存在
  是今天的常態，印了只會把真正該看的 warning 淹掉。
- 🔴 **換卡時四個 state 一起歸零**，漏掉 `mirror` 最兇：上一張卡的 URL 留在畫面上，按下去就
  是上一段那種「播出別句」。
- 🔴 **`playMirror` 一定要明寫 `setPlaybackRate(1)`**：rate 黏在 player 實例上、**不隨來源
  重設**。不寫就會繼承上一次的 0.7×，把離線生成的原生慢速**再時間伸縮一次**——正好是這條
  階梯存在的理由所要消滅的那種失真。

### ③ ①② 只在 practice 步驟出現；③ 原音兩步都在、永遠可按

confirm 步驟抽掉聲音等於要人憑幾天前的記憶下判斷（65d8e9b 的教訓：實測 9 張滑掉 7 張、
confirm rate 0%），所以 ③ 兩步都渲染。但 ①② 把句子切成塊、把邊界唸出來，**等同提示**；
出現在 confirm 步驟就把聽力題變成閱讀題。

### ④ 診斷延後：閘門是 `noticed !== null`，而且延後的是**顯示**不是抓取

診斷先出現的話，後續每一個反應都被它錨定，量到的是「他同意 app 的猜測」而不是他自己的
noticing。**這個 app 唯一的資產就是學習者自己指出來的斷點，被自家的猜測污染等於自斷來源。**

`onReveal` **照舊在揭露當下就發出診斷請求**，他思考的那幾秒剛好蓋掉 round trip——
**延後不該變慢**。閘門必須是 `noticed`，不能是 `diagnosing`（見上表）。

### ⑤ 三個答案，`segmentation` 自成一格

「就是這幾個字」／「我切不出這裡有幾個字」／「跳過」。

- token **只准選連續一段**：聽力的斷點是連續的一段聲音。准他東點一個西點一個，收到的是
  「這幾個字我都不太熟」，那與「我卡在這裡」不是同一件事。
- **「切不出有幾個字」不是「不知道」**：那是**詞界切分失敗**（Field 2003），是這個產品獨有
  的那一格資料，所以給它自己的按鈕，不併進跳過。
- **`skip` 不顯示對照列**——他沒給答案，硬比就是替他捏造一個。

### ⑥ 對照列以**詞**為單位比，不准裸 `includes`

`'gonna'.includes('on')`、`'they'.includes('the')`、`'stop'.includes('to')` 全是 true，而
noticing 的 token 與 `focus_phrase` 來自**同一句**，碰撞率極高。判準改成：一方的整串詞是
另一方的**連續子序列**（`sameNoticeSpan`）；大小寫與標點在 `normalizeNotice` 就磨掉，
所以 "Wanna go," 與 "wanna go" 仍是同一處。

不能將就的理由：**「他圈的 vs 我們判斷的」一致率是診斷延後唯一要產出的那個數字**，而裸
includes 的偏差**剛好偏向「同意」**——那正是延後診斷要消滅的錨定效應，只是換個地方發生。

不一致時寫「**不同處——先信你圈的**」不是客套：他圈的是他當下真的卡住的地方，診斷只是一次
**沒有聽覺輸入**的文字推測。這一格不一致本身就是資料（CONTEXT.md：`selection_kind` 與
`DiagnosisType` 的落差是資料不是錯誤）。

## Consequences

**誠實記錄——本輪最重要的一段：**

- 🔴 **沒有任何 Mirror 音檔存在。** `checkMirrorAssets` 對每一張卡都回 `'missing'`，
  `mirrorLadder` 恆為 `false`，**這條路徑從未實際播放過一次**。Decision ① 那四點音訊論證是
  **論證，不是實測結果**：它決定了我們要生什麼檔，**不代表生出來的檔真的比 0.7× 有效**。
  要驗證得先有檔（本機 IndexTTS-2，`/indextts-setup`，下一輪）。
- 素材查不到時，重聽那一塊與改版前**一個像素都不差**（0.7× 那顆膠囊照舊）。這是本輪的降級
  保證：**階梯是加法**，沒有素材就不存在。
- **`0.7×` 沒有被刪掉，這不是矛盾。** 它的問題是不該**冒充**第二級，不是它一無是處；沒有
  Mirror 素材時它仍是唯一的慢速。
- 🔴 **名字先於東西：現在叫「Mirror」的這條路徑不在使用者自己的聲音裡。** ADR-0009 的 Mirror
  是 golden-speaker（學習者自己的克隆聲音）；本輪的路徑是 `demo-media/<slug>/mirror/`，
  **沒有 user id**，一集一份、所有人共用。它是階梯的骨架，**不是** 0009 的 Mirror。哪天要接
  0009，路徑要多一層身份，`deriveMirrorPaths` 的簽章會變——現在就寫下來，免得到時有人以為
  只要換個 bucket。
- `'missing'` **也快取**（不快取則每次換卡都打兩次網路，而今天每張卡都 missing）。代價：素材
  上架後要重開 app 或呼叫 `resetMirrorCache()`。prototype 階段接受。
- 🔴 **noticing 的答案量不到。** `NoticeAnswer` 只活在 component state，關掉畫面就消失：
  `Capture`（`types.ts`）沒有這個欄位，而 migration 006 連現有欄位都還沒上線（實測
  `selection_text` 回 **42703**）。所以「他圈的 vs 我們判斷的」一致率——本 ADR 唯一要產出的
  那個數字——**今天只在畫面上出現一次，沒有進任何地方**。記在這裡而不是偷偷補一個 capture
  欄位：那會在 006 之上再疊一層未上線的 schema 債，而且會讓「寫進去了」變成一句假話。
  （與 ADR-0022 follow-up 是同一筆。）
- **診斷延後多了一次點擊。** 既有使用者（1 位）會覺得多一步；`skip` 是給他的出口。但**按跳過
  的人不產生那個數字**。若之後量到多數人都按跳過，該檢討的是問法，**不是把延後拿掉**——
  拿掉就回到錨定，那個數字會變成一個好看的假貨。
- **評分機制（再來一次／記住了／太簡單）一行未動。** 它是另一個待決定的題目。

**沒有 supersede 任何 ADR。** ADR-0009 是素材產線（誰的聲音、用什麼引擎生），本份是播放端
（有哪幾級、查不到怎麼辦），兩者在 `mirror/` 的命名契約上交會；ADR-0012「一個 capture 一個
learning focus」不變——noticing 收的是**他的**那一個，不是第二個 focus；ADR-0017 的框選訊號
不變，noticing 不寫進 `captures`，**不是**新的訊號來源。
