# ADR-0018 — 玻璃材質層用疊層自己做，不裝原生模組；材質與語意分開兩套 token

- **Status:** accepted
- **Date:** 2026-08-11

## Context

W6 的改版要把整個 app 換成 Apple 式的「漸層透明」質感（首頁 bento、逐字稿框選的
浮動動作列、練習頁的區塊）。三個力量同時壓在這個決定上：

1. **六天內只能靠 OTA 迭代。** Pre-Demo Day 是 8/17。Expo SDK 57 確實有第一方的
   `expo-blur`、`expo-linear-gradient`、`expo-glass-effect`、`expo-mesh-gradient`，
   但四個都是原生模組——加進去就得重新 build 一版丟給使用者，之後每個視覺微調
   都要重跑一次。這六天的節奏承受不起。
2. **質感必須是一套，不是六套。** 這一輪有七個平行代理在改六個畫面。沒有共用
   primitive 的話，「浮起來的面板」會在每個畫面長得不一樣：邊框有的用 `C.border`
   有的用白色半透明、陰影六份不同配方、色暈想放就放。
3. **`theme.ts` 只有一條鐵律：顏色帶語意，不准重用**（綠＝學習者動手了／琥珀＝
   app 在猜／藍＝中性 chrome）。材質 token（白色半透明填色、陰影、凹槽）**不帶
   語意**，直接塞進 `C` 會稀釋那條鐵律——`C` 的契約是「每個 key 是一個語意色」。

考慮過的選項：

- **裝 `expo-blur` + `expo-linear-gradient`** —— 質感最好，但要重新 build，違反 (1)。
- **每個畫面各自寫 rgba** —— 零成本起步，但違反 (2)，而且色碼寫死在元件裡本來就
  是 `theme.ts` 檔頭明令禁止的。
- **抽 `Glass` / `Gradient` 兩個 primitive + 四組材質 token** —— 選這個。

## Decision

**材質用疊層自己做，並且與語意色徹底分家。**

`lib/theme.ts` 新增四個獨立 export（**不放進 `C`**）：`GLASS`（填色／邊框／上緣高光
／凹槽／遮罩）、`BLOOM`（三個語意色暈）、`RAMP`（同色相三段濃度）、`ELEV`（兩階陰影）。
`C` 只多一個 key：`accentSurface`——它是綠色的行內半透明表面，語意與 `accent` 完全
同一件事（學習者親手圈出來的字），所以留在 `C` 是對的。

玻璃＝三層疊出來，缺一不可：

```
底填 rgba(255,255,255,0.055)      ← 面板本體
上緣 1px rgba(255,255,255,0.14)   ← 光線打在上緣的折射，玻璃感的唯一來源
外框 1px rgba(255,255,255,0.08)   ← hairline
（可選）背後一顆低透明度的語意色圓 ← mesh gradient 的錯覺
```

真・毛玻璃比這個多的只有背景模糊，而我們的背景是純色 `C.bg`——模糊純色等於沒模糊。
**上緣那條 1px 不是裝飾，是整個材質的定義**；拿掉之後剩下的只是一張半透明灰卡片，
所以 `Glass` 的 `sheen` 預設 true，只有面板頂端確定被別的東西蓋住時才關。

漸層＝`<Gradient>`，N 條絕對定位的 View 各填一個內插色。深底上 12~16 條就看不出
色帶。條與條之間刻意重疊 0.5%，否則百分比取整會留下髮絲縫。

**兩條配套鐵律寫進 `theme.ts` 的檔頭，因為不寫死必然漂移：**

- `C.border`（不透明）只用在非玻璃的既有元件；`GLASS.edge` 只用在玻璃面板，同一個
  View 上兩者不得並存。
- **bloom 只能用該面板已經憑語意賺到的色相。** 沒有語意可用的面板就不放 bloom，
  不是隨便挑一個好看的。綠色一旦出現在跟「學習者動手了」無關的地方，它就不再是
  那個訊號的化身——而整個產品的論點就是那個訊號。

## Consequences

**變容易的**：六個畫面用同一支 `Glass`，「浮起來」在全 app 是同一個高度、同一種
邊。要調整整體質感（例如底填從 0.055 調到 0.07）只改 `theme.ts` 一個字。`ELEV`
收掉了原本只存在於 `Artwork.tsx` 的那份陰影配方。

**變難的 / 被綁住的**：

- **沒有真正的背景模糊。** 只要哪天內容會透過面板（例如面板浮在封面圖上），這個
  近似就會露餡。屆時要 supersede 這份、改裝 `expo-blur`，並接受一次 rebuild。
- **`Gradient` 是 N 個 View。** 因此規格層級限制「每畫面最多一個 `<Gradient>`」，
  masonry 卡片、晶片、逐字稿的列一律禁用。這個上限沒有寫在型別裡，靠 review 守。
- **不做 radial gradient。** 放射狀要靠同心圓疊層，數量級是 N² 個 View；「面板背後
  一團色暈」的需求由 `Glass` 的 bloom（單顆大圓）解掉，兩份實作只會互相走鐘。
- `elevated` 的 `Glass` 會多一層 View（陰影不能畫在 `overflow:'hidden'` 上，iOS 的
  `clipsToBounds` 會把自己的陰影剪掉），而且外層帶一個不透明的 `C.bg` 底色讓 iOS
  畫得出便宜的 `shadowPath`。因此 elevated 的面板**不能**浮在頁面底色以外的東西上。
- `C.faint` 從此禁止出現在玻璃或 bloom 上：它的 5.1:1 / 4.6:1 是對 `bg` / `surface`
  實算的，玻璃底下是變數，會掉到 AA 以下。玻璃上的次要文字一律 `C.dim`。

**沒有 supersede 任何 ADR。** ADR-0001（Expo 原生 app）不變——這份反而是它的直接
後果：正因為我們有原生殼，才必須避免任何會逼使用者重新安裝的相依。
